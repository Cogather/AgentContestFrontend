## 前端交互测试用例

### 测试准备

#### 环境

- 前端地址
  - `http://localhost:5173/`
  - 启动命令：`npm run dev -- --host 0.0.0.0`
- 后端地址
  - `http://localhost:8080`
  - 前端通过 `VITE_API_BASE_URL` 配置
- 默认赛程
  - 开始：`2026-05-24T08:00:00-07:00`
  - 结束：`2026-06-15T00:00:00-07:00`
  - 文案：`2026/5/24 8:00--2026/6/14`

#### 测试账号

- `00000000`
  - 用途：已有多条提交
  - 覆盖：历史记录、冷却、失败原因、得分详情
- `10000001`
  - 用途：排行榜提交次数验证
  - 期望：接口可返回 `submission_count`
- `99999999`
  - 用途：不存在用户
  - 覆盖：新用户注册、登录异常

#### 通用清理

- 清空 localStorage
  - `agent_game_user`
  - `agent_game_third_party_user_id`
- 刷新页面
- 确认没有旧用户态残留

### 初始化与工号识别

#### 无工号访问

- 用例编号：`FE-INIT-001`
- 优先级：P0
- 路径
  - 打开 `/`
- 期望
  - 进入登录页
  - 工号显示“等待第三方登录返回工号”
  - 登录按钮禁用
  - 不显示主页内容
- 边界
  - 页面不应空白
  - 初始化不应闪入主页

#### URL 工号识别

- 用例编号：`FE-INIT-002`
- 优先级：P0
- 路径
  - 打开 `/?user_id=00000000`
- 期望
  - 查询用户成功后进入主页
  - 顶部显示当前用户昵称
  - 参赛信息显示工号
  - localStorage 写入第三方工号
- 边界
  - 历史接口慢时主页仍能渲染

#### 多 query key 识别

- 用例编号：`FE-INIT-003`
- 优先级：P1
- 输入
  - `user_id`
  - `userId`
  - `employee_id`
  - `employeeId`
  - `work_id`
  - `workId`
- 期望
  - 都能识别 8 位工号
  - 已存在用户进入主页
- 边界
  - 多个 key 同时存在时按代码优先级取第一个有效值

#### 工号规范化

- 用例编号：`FE-INIT-004`
- 优先级：P1
- 输入
  - `abc00000000xyz`
    - 期望识别为 `00000000`
  - `1234567`
    - 期望无效
  - `123456789`
    - 期望取 `12345678`
  - `abcd`
    - 期望无效
- 边界
  - 只保留数字
  - 最多取前 8 位
  - 不展示非数字字符

#### localStorage 兜底

- 用例编号：`FE-INIT-005`
- 优先级：P1
- 前置
  - localStorage 中有 `agent_game_third_party_user_id=00000000`
  - URL 无 query
- 期望
  - 使用 localStorage 工号查询用户
  - 用户存在则进入主页
- 边界
  - URL 有新有效工号时覆盖 localStorage

#### 已存用户不存在

- 用例编号：`FE-INIT-006`
- 优先级：P0
- 前置
  - localStorage 中有旧 `agent_game_user`
- 路径
  - 打开 `/?user_id=99999999`
- 期望
  - 展示登录页
  - 工号显示 `99999999`
  - 清理旧 `agent_game_user`
- 边界
  - 404 不展示网络错误
  - 不应展示旧用户主页

#### 查询用户接口异常

- 用例编号：`FE-INIT-007`
- 优先级：P1
- 异常
  - HTTP 500
  - 网络断开
  - 超时
- 期望
  - 进入登录页
  - UI 不崩溃
  - `sessionReady` 最终完成

#### 登录业务失败

- 用例编号：`FE-LOGIN-006`

#### 登录网络异常

- 用例编号：`FE-LOGIN-007`
- 优先级：P1

### 赛程与上传入口

#### 比赛未开始

- 用例编号：`FE-SCHEDULE-001`
- 优先级：P0
- 前置

- 边界

#### 比赛进行中

- 用例编号：`FE-SCHEDULE-002`
- 优先级：P0
- 前置

  - 无冷却
- 期望

  - 上传按钮文案“上传代码”
  - 上传按钮可点击
- 边界
  - 不出现“当前比赛中”等额外文案

#### 比赛已结束

- 用例编号：`FE-SCHEDULE-003`
- 优先级：P0
- 前置
  - 当前时间晚于结束时间
- 期望
  - 倒计时显示“已结束”
  - 不显示“距离...”标签
  - 上传按钮文案“个人赛已结束”
  - 上传按钮禁用
  - 提示“提交通道已关闭”

#### 比赛时间非法

- 用例编号：`FE-SCHEDULE-004`
- 优先级：P1
- 输入
  - 非法开始时间
  - 非法结束时间
- 期望
  - 倒计时显示“待定”
  - 页面不崩溃
- 风险
  - 当前未知阶段可能仍允许上传
  - 需要产品确认是否应强制禁用

#### 上传冷却中

- 用例编号：`FE-SCHEDULE-005`
- 优先级：P0
- 前置
  - 历史最新提交距离当前不足 30 分钟
- 期望
  - 按钮显示 `MM:SS 后可上传`
  - 按钮禁用
  - 提示“每次上传间隔需满30分钟”
  - 每秒倒计时减少
- 边界
  - 小于 10 秒时补零
  - 冷却结束后自动恢复“上传代码”

#### 历史提交时间异常

- 用例编号：`FE-SCHEDULE-006`
- 优先级：P1
- 输入
  - `created_at=null`
  - `created_at=''`
  - `created_at='invalid'`
- 期望
  - 非法时间不参与冷却计算
  - 没有合法时间则不冷却
  - 页面不出现 `NaN`

#### 合法 score_detail

- 用例编号：`FE-DETAIL-005`
- 优先级：P0
- 输入
  - 10 道题 JSON 数组
  - 字段：`question`、`score`、`total`
- 期望
  - 按 `question` 升序
  - 显示接口分数

#### 空或非法 score_detail

- 用例编号：`FE-DETAIL-006`
- 优先级：P0
- 输入
  - `null`
  - 空字符串
  - `invalid score detail`
  - 非数组 JSON
- 期望
  - 已完成且有总分的提交不展示“得分详情”
  - 列表显示“暂无明细”

#### score_detail 字段边界

- 用例编号：`FE-DETAIL-007`
- 优先级：P1
- 输入
  - 缺 `question`
  - 使用 `id`
  - 缺 `total`
  - 使用 `fullScore`
  - 使用 `max_score`
  - score 非数字
  - question 小于 1 或大于 10
- 期望
  - 合法题号保留
  - 非法题号过滤
  - score 非数字或 total 非法的数据不参与展示
  - 已完成且有总分的提交不满 10 题则不展示“得分详情”

- 用例编号：`FE-DETAIL-008`
- 优先级：P0

  - 空数组
  - 只有 1 到 9 题
  - 非数组
- 期望
