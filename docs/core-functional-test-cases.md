# AgentContest 前后端核心功能测试用例

> 范围：西研软件大赛个人赛前端、Spring Boot 后端、MySQL 数据、上传包分发目录、排行榜、历史提交、应急登录与运维辅助接口。  
> 分层：L0 为上线前必须通过的阻塞级冒烟用例；L1 为主流程和核心回归；L2 为边界、安全、兼容和运维类补充用例。
> 使用方式：每次发布先跑 L0；命中对应模块改动时补跑 L1；涉及部署、数据迁移、比赛时间、登录链路、文件挂载时补跑 L2。

## 测试前置

- 前端已部署或本地启动：`npm run dev -- --host 0.0.0.0` 或生产静态站点。
- 后端已启动，`GET /api/contest/config` 返回 `code=0`。
- 浏览器清理以下 localStorage 后开始测试：`agent_game_user`、`agent_game_third_party_user_id`。
- 数据库准备至少 4 类账号：
  - 普通新用户：未存在于 `users`。
  - 普通老用户：存在于 `users`，有 Cookie 登录能力。
  - 测试账号：存在于 `users` 和 `test_accounts`，用于验证特权上传和排行榜“官方Demo”标注。
  - 应急账号：存在于 `users` 和启用状态的 `emergency_login_accounts`。
- 准备上传包：
  - 合法 zip：包含 `start.sh`，且 `start.sh` 换行符为 LF。
  - 非 zip 文件、坏 zip、缺少 `start.sh` 的 zip、`start.sh` 为 CRLF 的 zip。
  - 接近 100MB 的合法 zip。
- 后端配置确认：
  - `APP_COMPETITION_START_AT`、`APP_COMPETITION_END_AT` 为北京时间。
  - `APP_UPLOAD_DIR`、`APP_DISTRIBUTION_DIR`、`APP_DISTRIBUTION_TARGET_DIRS` 可写。
  - 如开启写接口保护，前端配置 `VITE_WRITE_API_KEY` 与后端 `APP_WRITE_API_KEY` 一致。

## L0 阻塞级冒烟用例

| ID | 覆盖端 | 功能 | 前置 | 步骤 | 预期 |
|---|---|---|---|---|---|
| L0-001 | 前端/后端 | 应用启动与配置加载 | 前端可访问，后端可访问 | 打开首页；观察 `/api/contest/config` | 页面非空白；标题、赛程、倒计时从后端或默认配置渲染；接口失败时前端可用默认配置兜底 |
| L0-002 | 前端/后端 | 第三方工号进入登录页 | 无有效 Cookie，URL 带 `?user_id=<8位工号>` | 打开首页 | 工号被规范化为 8 位数字；若用户不存在，显示“参赛登录”和昵称输入框；登录按钮在无昵称时不可提交 |
| L0-003 | 前端/后端/数据库 | 新用户首次登录 | `users` 中无该工号 | 输入昵称并点击登录 | `POST /api/users` 成功；后端写入用户并签发 Cookie；前端进入主页；昵称设置后不可修改 |
| L0-004 | 前端/后端 | 老用户自动进入主页 | `users` 中已有该用户，Cookie 有效 | 刷新首页 | `GET /api/users/me` 成功；无需身份确认页；直接进入主页 |
| L0-005 | 前端/后端/文件系统 | 合法 zip 上传成功 | 普通账号在比赛时间内且无冷却；分发目录可写 | 上传包含 LF `start.sh` 的 zip | 前端显示上传中动画后成功状态；后端返回 `UPLOADED`；`submissions` 写入 `original_file_path`、`stored_file_path`、`submit_ip`；本机和所有挂载目标目录均存在 `{submissionId}.zip` |
| L0-006 | 前端/后端 | 上传失败错误展示 | 准备非 zip 或缺 `start.sh` 的包 | 在上传弹框提交非法包 | 前端错误显示在上传框内，不弹原生 alert；后端返回明确错误；无成功提示；非法包不产生有效冷却 |
| L0-007 | 前端/后端/数据库 | 30 分钟上传间隔 | 普通账号刚成功上传一笔 | 立即再次上传合法包 | 后端拒绝并返回“距离上次上传不足X分钟”；前端展示后端错误；非成功上传不应刷新冷却 |
| L0-008 | 前端/后端 | 比赛时间窗口拦截 | 调整当前时间或配置为未开始/已结束 | 点击“上传代码”或直接调 `/api/upload/me` | 前端点击时给出“未到参赛时间，无法提交”或“个人赛已结束”；后端直接调用也必须拒绝 |
| L0-009 | 前端/后端 | 历史提交记录展示 | 当前用户有多条提交 | 进入历史提交页 | 表格展示提交 ID、时间、总分、Token、状态、操作；不展示服务器文件路径 |
| L0-010 | 前端/后端/数据库 | 得分详情展示 | 已完成提交含 `score_detail`，`question_details` 有 10 题 | 点击历史记录“查看详情” | 弹框展示题目目录和右侧题目详情；得分支持小数；题目详情中的 `\n` 按换行渲染 |
| L0-011 | 前端/后端/数据库 | 排行榜主流程 | 至少 2 个非测试用户有完成提交 | 查看排行榜 | 默认每页 20 条、左右各 10 条；展示排名、昵称、得分、提交次数、Token；第一名到第三名红色分级 |
| L0-012 | 前端/后端 | 排行榜测试账号标注 | `test_accounts` 中有测试账号 | 查看排行榜和参赛人数 | 测试账号行标注“官方Demo”；若用于正式名次统计，应确认测试账号不会影响正式用户排名口径 |
| L0-013 | 前端/后端/数据库 | 取消排队提交 | 当前用户有 `UPLOADED` 提交 | 历史页点击取消 | 状态变为 `CANCELED`；刷新后仍保持；提交次数相应减少；该用户下一次上传间隔按取消后规则重新计算 |
| L0-014 | 后端/脚本 | 日志下载 | 配置日志目录模板，存在 `<submissionId>/*.log` | 调用下载接口或 Python 脚本 | 密钥正确时下载该提交目录下的 `.log` 文件；密钥错误返回 403；无日志返回 404 |

## L1 核心回归用例

| ID | 覆盖端 | 功能 | 前置 | 步骤 | 预期 |
|---|---|---|---|---|---|
| L1-001 | 前端 | HTTP 强制跳 HTTPS | 非本地 HTTP 访问 | 打开 `http://正式域名/...` | 前端在启动前跳转到同路径 HTTPS；`localhost`、`127.0.0.1` 不跳转 |
| L1-002 | 前端 | 第三方登录守卫 | `VITE_ENABLE_LOGIN_GUARD=true`，localStorage 无工号 | 打开首页 | 跳转内部登录地址；回传工号后写入 `agent_game_third_party_user_id` 并回到前端 |
| L1-003 | 前端/后端 | localStorage 工号被修改 | 已用 A 用户 Cookie 登录，F12 改为 B 工号 | 调用历史、上传、个人排名接口 | 后端以 Cookie 用户为准；不允许用前端明文工号访问 B 数据；异常应写服务端身份校验日志 |
| L1-004 | 后端 | 会话 Cookie 缺失或篡改 | 清 Cookie 或改 Cookie 内容 | 调用 `/api/users/me`、`/api/upload/me`、`/api/rank/me` | 返回 401/403；不返回任何用户私有数据 |
| L1-005 | 前端/后端 | 应急登录 | 用户在 `emergency_login_accounts` 启用 | 打开 `/emergency-login`，输入工号 | 不经过第三方登录；后端校验白名单；成功签 Cookie 并进入主页 |
| L1-006 | 前端/后端 | 应急登录拒绝 | 用户未启用应急登录 | 打开 `/emergency-login` 输入工号 | 返回“未开通应急登录”；不签 Cookie；停留应急登录页 |
| L1-007 | 后端/数据库 | 昵称不可修改 | 用户已存在并有昵称 | 调 `PUT /api/users/me` 传不同昵称 | 返回业务错误；数据库昵称不变 |
| L1-008 | 后端 | 写接口 key | 设置 `APP_WRITE_API_KEY` | 无 key/错误 key/正确 key 分别调用写接口 | 无 key 和错误 key 拒绝；正确 key 允许；GET 接口不要求 key |
| L1-009 | 后端 | CORS 配置 | 配置真实前端域名 | 从允许域名和非允许域名发起跨域请求 | 允许域名正常；非允许域名被浏览器拦截或无 CORS 许可 |
| L1-010 | 前端/后端 | 上传 100MB 限制提示 | 准备 100MB 内合法 zip 和超限 zip | 分别上传 | 100MB 内可进入后端处理；超限返回 413 或明确错误；前端展示“100MB zip”限制 |
| L1-011 | 后端 | zip 解压安全 | 准备 zip slip、超文件数、超单文件、超总解压体积包 | 逐个上传 | 后端全部拒绝；临时目录被清理；不写成功提交 |
| L1-012 | 后端 | `start.sh` 换行符校验 | zip 内 `start.sh` 为 CRLF | 上传 | 返回换行符错误；不分发程序包；不形成有效冷却 |
| L1-013 | 后端/数据库 | 分发 all-or-fail | 配置两个挂载目标，其中一个不可写 | 上传合法包 | 返回失败；提交状态 `FAILED`；`error_message` 写明失败目录；不会告诉用户上传成功 |
| L1-014 | 后端/数据库 | 上传路径字段 | 上传成功 | 查询 `submissions` | `stored_file_path` 为最终分发绝对 zip 路径；`original_file_path` 为接收目录绝对 zip 路径；文件名均为 `{id}.zip` |
| L1-015 | 后端/数据库 | 提交 IP | 通过代理和非代理请求上传 | 检查 `submit_ip` | 优先识别可信转发头；超过 64 字符被截断；为空时允许 null |
| L1-016 | 前端/后端 | 上传并发闸门 | 同一用户快速双击上传或并发发起两个请求 | 观察前端和数据库 | 前端按钮上传中不可重复提交；后端用户锁防止绕过冷却；不会出现两笔同时有效成功 |
| L1-017 | 后端/数据库 | 夜间放开间隔 | 上传间隔配置为 30 分钟，当前北京时间 22:00-08:00 | 连续上传两笔合法包 | 后端不按 30 分钟拦截；白天同样步骤仍拦截 |
| L1-018 | 后端/数据库 | 动态上传间隔 | 修改 `app_settings.upload_interval_minutes` | 不重启服务，连续上传 | 后端按数据库新值生效；设置为 0 或负数时不拦截 |
| L1-019 | 前端/后端/数据库 | 队列状态 | 多个 `UPLOADED` 提交 | 查看历史页和 `/api/users/me/submissions/summary` | 显示“当前排队/正在评测”数量；每笔排队提交显示前方还有多少笔 |
| L1-020 | 前端/后端 | 取消状态限制 | 当前用户有 `UPLOADED`、`EVALUATING`、`FAILED`、`COMPLETED` | 在历史页操作 | 只有 `UPLOADED` 显示并允许取消；`EVALUATING`、`FAILED`、`COMPLETED` 不允许取消 |
| L1-021 | 后端 | 取消权限 | 用户 A 尝试取消用户 B 的提交 | 调 `/api/users/me/submissions/{id}/cancel` | 返回 403；B 的提交状态不变 |
| L1-022 | 前端 | 历史刷新 | 历史页点击刷新 | 观察列表和顶部队列统计 | 历史列表、排队数、评测数同时刷新；错误时不无限弹提示 |
| L1-023 | 前端/后端 | 失败原因展示 | 提交 `FAILED` 且有 `error_message` | 历史页查看失败提交 | 状态展示“失败”；点击或详情可看到换行后的失败原因 |
| L1-024 | 前端/后端/数据库 | `score_detail` 解析 | `score_detail` 为合法 10 题 JSON，小数分 | 点击查看详情 | 按题号升序；显示 `score / total`；小数不被截断；总分与列表一致 |
| L1-025 | 前端 | 得分详情缺失 | `score_detail` 为空、非法 JSON 或题目详情不足 | 查看历史详情入口 | 不使用本地写死题目或分数；展示“暂无明细/待评测/无得分”等不可点击状态 |
| L1-026 | 前端 | 题目详情长文本 | 每题详情约 2000 字且包含换行 | 打开查看详情 | 左侧目录不突兀，右侧详情可独立滚动；`\n` 按换行显示；弹框不撑破视口 |

## 推荐执行策略

- 每次生产发布前必须执行全部 L0。
- 涉及登录、上传、排行榜、历史提交、数据库结构、部署配置任一改动时，至少执行相关 L1。
- 比赛开始前、结束前、服务器迁移、挂载目录调整、内部登录服务调整时，执行对应 L2。
- 自动化建议：
  - 前端保持 `npm test -- scripts/frontend-regression.test.mjs` 和 `npm run build` 作为基础门禁。
  - 后端保持 `mvn test` 和 `mvn -DskipTests package` 作为基础门禁。
  - L0 中的上传、取消、排行榜、日志下载建议沉淀为接口级 smoke 脚本，减少手工遗漏。
